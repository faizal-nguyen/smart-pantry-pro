## 1. Schéma déployé

### Fonction de commande

L'empreinte md5 du corps de `private.execute_stock_command` déployé est `16d15738f7b462ecfae4fb6d271a3e16` (30 223 caractères). C'est exactement le corps de [20261108120000_menu_shopping_commands.sql](../../supabase/migrations/20261108120000_menu_shopping_commands.sql). E2 part donc de cette version.

```sql
SELECT n.nspname, p.proname, md5(p.prosrc), length(p.prosrc)
FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE p.proname = 'execute_stock_command';
```

| `priority` | `integer DEFAULT 1` | |
| `estimated_price` | `numeric` | |
| `store_section` | `text` | |
| `unit` | `text` | |

Les colonnes de la migration `20250818000001` (`shared_list_id`, `notes`, `purchased_at`, `shopping_pattern_order`, `discount`) **n'existent pas** en production, pas plus que `name`, `list_id` ou `is_checked`, que lisent les routes historiques `/api/v1/shopping/*`.

- **Droits :** `authenticated` a `arwdm` (lecture, insertion, modification, suppression), d'où une écriture directe ouverte jusqu'à D15. `anon` n'a aucun droit. RLS active, quatre politiques par propriétaire (`auth.uid() = user_id`).
- **Déclencheurs :** `update_shopping_list_updated_at`, `v10_shopping_version` (incrément de `stock_version`), `v10_shopping_unit` (unité requise, quantité valide), `v10_shopping_cache`.

### `public.products`

- Index unique `idx_products_normalized_name_unique` sur `normalized_name`, alimenté par le déclencheur `trg_products_normalize_name` : `lower(unaccent(trim(name)))`, avec `public.unaccent`.
- La résolution par nom des commandes (`stock_normalize_name` : décomposition NFD, minuscules, espaces réduits) **ne correspond pas** à cette normalisation. Exemple : « Bœuf » (`stock_normalize_name` = `bœuf`) n'est pas trouvé quand « Boeuf » existe. L'insertion qui suit heurte alors l'index unique (`normalized_name` = `boeuf`) et la commande échoue en 500.
- Le déclencheur appelle `unaccent()` sans schéma et n'a pas de `search_path` propre (`proconfig` vide). Or les fonctions de commande tournent avec `search_path=''`. Toute création de produit depuis une commande échoue donc en production (« function unaccent(text) does not exist »).
- `recipe_add_missing` présente ces deux défauts, sans qu'ils soient apparus, puisqu'elle n'a jamais été exécutée. E2 les corrige par une résolution commune (`private.shopping_resolve_product`), exécutée avec `search_path=pg_catalog,public`.

### Tables absentes en production

`store_layouts`, `store_sections`, `shared_shopping_lists`, `shopping_list_collaborators`, `live_shopping_sessions`, `shopping_patterns`, `product_prices`. Le déclencheur `create_default_shopping_list_trigger` sur `auth.users` est absent lui aussi.

Les tables « orphelines » de la section 12 de la PRP n'existent donc que dans la chaîne locale. Information transmise à V11-06 E0 et E8.

## 4. Faits pour E3

| Mesure | Valeur |
| --- | --- |
| Lots de stock | 157, sur 1 compte |
| Lots sans date | 155 |
| Zones (`inventory.location`) | vide : 149 ; `congélateur` : 7 ; `Réfrigérateur` : 1 |

Conséquences pour E3 :
- La migration des zones est minime. « congélateur » et « Réfrigérateur » se rapprochent des emplacements de base par clé normalisée. Les 149 lots sans zone forment le groupe « À ranger ».
- Les rachats fréquents (D10) ne peuvent pas être calibrés sur des données réelles, puisqu'aucun rangement par commande n'a eu lieu. La règle et la fenêtre seront fixées par défaut, puis revues après usage.
- Les prix existants sont tous positifs ou vides : la reprise vers `estimated_line_price` (E6, D9) n'a aucun `0` ambigu à traiter.
