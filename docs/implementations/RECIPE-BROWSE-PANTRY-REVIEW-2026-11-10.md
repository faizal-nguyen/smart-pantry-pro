# Recipe browsing, chef retrieval and produce review

- Recipe titles: a guarded dry-run/compare-and-set script removes redundant pork/alcohol qualifiers from 13 owned titles. No ingredient, nutrition, photo or dietary-policy changes. The prior title and timestamp are journaled. Initial classic-import scripts intentionally reject later edits; do not reimport over the user's library.
- Cuisine: one shared French/English alias registry drives the library and recommendation engine. The URL stores the filter. Catalog origin is read from its tags: the live table has no `cuisine_category` column. No schema change or unsupported SQL filter is required.
- Retrieval: shared title matching ignores connecting words, normalizes accents/plurals and tolerates bounded typos. Short words stay exact (`riz` is not `ris`). Named stock comparisons use the existing common evaluator. Model transport now preserves purchase-versus-quantity reasons, essential flags, and completeness instead of dropping gaps after the first three. Profile-sharing gates are unchanged.
- Return position: account-scoped session storage records the exact list URL, clicked card and viewport offset. Restoration waits for asynchronous data and reloads previously loaded catalog pages when needed. Both browser Back and the detail toolbar return to the original filtered list; focus follows the restored card.
- Produce review: in-app reminders use time since the latest inventory update. Leafy herbs/greens: 3 days; broccoli/mushrooms/fragile fruit: 5; common fruit/vegetables: 7; roots/onions/garlic/squash: 14. These are **review cadences, not shelf-life estimates**. Frozen, processed, dry, empty and undated lots are excluded. Existing database timestamps are used, not inferred purchase dates.
- “J’en ai encore” sends an existing versioned/idempotent adjust command with unchanged stock facts; the database's update trigger refreshes the timestamp across devices. It does not change expiry, quantity quality or conservation notes. “Tout consommé” uses the existing consumption command and undo. Corrections and waste declarations reuse existing dialogs; age reminders default waste reason to `other`, not `expired`. No automatic stock deletion or expiry decision.
