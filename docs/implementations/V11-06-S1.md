## 5. Production

**Ordre d'application.** Les quatre migrations sont indépendantes et idempotentes. Ordre conseillé : `20261127120000`, `20261127120100`, `20261127120200`, `20261127120300`. Le code peut être déployé avant ou après : il ne dépend d'aucune.

**Vérification après application** (éditeur SQL) :

```sql
-- 1. Stockage : exactement ces quatre politiques pour product-images, aucune pour temp-ocr.
SELECT policyname, cmd FROM pg_policies
WHERE schemaname = 'storage' AND tablename = 'objects'
  AND (coalesce(qual, '') || coalesce(with_check, '')) ~ '(product-images|temp-ocr)'
ORDER BY policyname;
-- attendu : product_images_delete_own, product_images_insert, product_images_select_own, product_images_update_own
SELECT public, file_size_limit, allowed_mime_types FROM storage.buckets WHERE id = 'product-images';
-- attendu : true, 10485760, {image/jpeg,image/png,image/webp,image/heic,image/heif}

-- 2. Réglages : plus aucun droit d'écriture pour les rôles du navigateur.
SELECT grantee, privilege_type FROM information_schema.role_table_grants
WHERE table_schema = 'public' AND table_name = 'user_privacy_settings' AND grantee IN ('authenticated', 'anon')
ORDER BY grantee, privilege_type;
-- attendu : une seule ligne, authenticated SELECT

-- 3. Suppression : la fonction efface le profil.
SELECT position('user_profiles' IN prosrc) > 0 AS efface_le_profil FROM pg_proc WHERE proname = 'delete_user_rows';
-- attendu : true

-- 4. Export : dynamique, gardé, fermé aux anonymes.
SELECT position('pg_attribute' IN prosrc) > 0 AS dynamique, position('auth.uid()' IN prosrc) > 0 AS garde,
       has_function_privilege('anon', 'public.export_user_data(uuid)', 'EXECUTE') AS anon_peut_exporter
FROM pg_proc WHERE proname = 'export_user_data';
-- attendu : true, true, false
```

## 8. Signalés, hors de ce lot

- **Écritures directes encore permises** par la RLS sur `inventory`, `shopping_list` et `meal_plan_entries`, pour les lignes du compte, sans passer par les commandes. Relève de V11-05.
- **Nouveaux lots de stock** insérés hors commandes : formulaire, scan, ajout rapide, assistant.
- **Journaux du serveur** : `errorHandler` inscrit le `userId` et le message d'erreur. À décrire dans la politique (E7).
- **Buckets inutilisés** : `recipe-import-media` et `temp-ocr`, désormais fermé, à supprimer en E8.
- **Photos de recette déjà déposées** : elles gardent leurs métadonnées. Un nettoyage serait une décision à part.
- **Taille de l'export** : l'API le renvoie en une réponse, que Vercel plafonne à 4,5 Mo. Il contient désormais aussi les mouvements de stock et le journal des actions. Au-delà de 4 Mo, il est refusé par un message clair, ce qui reste un refus du droit d'accès. Un export par morceaux, ou en fichier dans un bucket privé avec une URL signée, serait un lot à part, à ouvrir si la taille réelle s'en approche.
- **Profil effacé** : `GET /v1/users/me` répond ensuite 404 ; aucun écran ne l'appelle (E0).
- **Photos de produits** : un fichier ancien sans `owner_id` ne peut plus être supprimé par son auteur ; `remove` ne signale pas un refus ; si `compressImage` échoue à produire une image, il envoie le fichier brut, avec ses métadonnées.
- **Photo de recette** : un PNG transparent devient noir en JPEG ; après un échec d'envoi, la recette est enregistrée avec l'ancienne image (comportement antérieur).
- **Tables sans `user_id`** (par exemple `shopping_list_collaborators`) : hors de l'export comme de la suppression, comme avant.
