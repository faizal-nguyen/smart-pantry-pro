# V11-01 E3d — Glisser-déposer des repas dans le menu

> Date : 25 novembre 2026.
> PRP : [V11-01](../../PRP/V11/PRP-V11-01-Boucle-Menus-Courses.md), section 5, décision D5 : glisser-déposer au pointeur, et « Déplacer » au clavier et au lecteur d'écran ; un créneau occupé donne un échange atomique.
> - « Déplacer… » est livré depuis [E3b](V11-01-E3b.md). Le glisser-déposer avait été reporté à une étape séparée (choix de l'utilisateur, 24 novembre 2026) ; c'est cette étape.
> - Choix de l'utilisateur, 25 novembre 2026 :
>   - **glisser-déposer natif du navigateur**, sur la grille de sept colonnes (au moins 1100 px : souris, trackpad, iPad), sans dépendance. Sur téléphone, « Déplacer… » reste le geste ; il reste aussi partout, pour le clavier et le lecteur d'écran ;
>   - **le dépôt agit aussitôt**, échange compris, avec « Annuler ».
>
> **Aucune migration**, aucune retouche du serveur.

## 1. Changements

Le dépôt n'est qu'une autre façon de choisir le créneau. Il fait exactement ce que fait « Déplacer… » : `edit.move(repas, semaine, créneau, occupant)`, c'est-à-dire l'opération `move` d'`update_menu`. Un créneau occupé échange les deux repas en une transaction, et la base revérifie les versions.

- **Saisie** ([MenuEntryCard](../../src/components/meal-planning/MenuEntryCard.tsx)) :
  - sur la grille d'ordinateur seulement, une carte se saisit, avec un curseur « main » ; sa poignée (`aria-hidden`) est aussi une prise, puisque Firefox ne démarre aucun glisser depuis un bouton, comme le titre ;
  - l'état « tenu » suit à la tâche suivante, une fois l'image du glisser prise par le navigateur ;
  - l'identifiant du repas voyage sous un type propre à l'application (`application/x-smart-menu-entry`), jamais le nom en `text/plain` ;
  - pendant une modification en cours, rien ne se saisit (une à la fois, comme les autres actions).
- **Survol** ([MenuWeekGrid](../../src/components/meal-planning/MenuWeekGrid.tsx)) : le créneau dit en mots ce que fera le dépôt (`dropTarget` et `dropHint` dans [menuEdit.ts](../../src/lib/menuEdit.ts), tirés de `moveOptions`) :
  - « Déposer ici » sur un créneau libre ;
  - « Échanger avec « X » » sur un créneau occupé ;
  - sinon, la raison du refus : « Ce reste doit venir après son repas d'origine. », « « X » doit venir avant ses restes : l'échange est impossible. ».
  - Un créneau refusé n'accepte pas le dépôt, et le navigateur le montre. Sa propre place ne dit rien.
  - Un contour en tirets, ou destructif pour un refus, accompagne toujours le texte : jamais la seule couleur. Le texte se pose sur le bas du créneau, pour que la grille ne bouge pas sous le pointeur.
- **Dépôt** : la notice du menu l'annonce (« … déplacé : lundi · dîner. », « … et … échangés. ») et le focus va sur « Annuler », comme après les autres modifications. Un refus du serveur passe par la notice d'erreur existante, et le menu est relu.
- **Ailleurs** : Échap, ou un lâcher hors d'un créneau, ne change rien. Sur téléphone, aucune carte ne se saisit ; « Autres actions » garde « Déplacer… ».
- **La grille n'est jamais retenue.** Le repas est lâché dans plusieurs cas :
  - sa carte quitte la semaine ou change de créneau pendant le glisser (le navigateur n'envoie alors plus `dragend`) ;
  - une autre modification commence ;
  - la semaine change ;
  - un `dragend` ou un `drop` arrive à la fenêtre.
  Le dépôt est rejugé sur la semaine telle qu'elle est, avec la version actuelle du repas.
- **Chromium** : les boutons d'un créneau (« Choisir une recette », portions, actions d'une carte) recevaient `dragenter` mais aucun `dragover`. Le créneau ne disait donc rien et refusait le dépôt. Pendant qu'un repas est tenu, la grille porte `data-holding`, et le contenu des créneaux, hormis la carte tenue, laisse passer le pointeur : le créneau reçoit le survol partout.

## 2. Vérifications

- `npm run test:v10` : 636 tests client et 804 tests API passent. Les 12 nouveaux tests client couvrent :
  - `dropTarget` et `dropHint` : sa place, libre, échange, reste avant son repas, repas après ses restes, échange qui mettrait l'autre repas en faute ;
  - la grille : seules les cartes de la grille d'ordinateur se saisissent ; créneau libre, occupé ou refusé ; dépôt avec l'occupant ; lâcher ailleurs ; repas qui quitte la semaine ou change de créneau, semaine changée ; version actuelle envoyée ; rien tenu ni déposé pendant une modification ;
  - la carte : type propre, rien en `text/plain`, poignée décorative ;
  - la page : un dépôt envoie le même `move` que « Déplacer… », puis met le focus sur « Annuler ».
- `typecheck:app` : aucune nouvelle erreur. `lint:ci` : 0 erreur. `build` passe.
- **Banc visuel** (Chromium, glisser au pointeur réel, données fictives) :
  - à 1440 px, en thèmes clair et sombre : créneau libre (« Déposer ici »), dépôt, notice, focus sur « Annuler », « Annuler » ; échange refusé (raison affichée, rien ne bouge) ; échange permis ; reste avant son repas (raison, rien ne bouge) ; aucune erreur console ;
  - à 375 px : aucune poignée, aucune carte saisissable, « Déplacer… » présent ;
  - après la relecture : échange au pointeur depuis la poignée ; grille cliquable après chaque glisser.
  - C'est ce banc qui a révélé l'absence de `dragover` sur les boutons.

## 3. Relecture

Une relecture indépendante (`typescript-reviewer`) a confirmé :
- la reprise telle quelle de `moveOptions` ;
- le refus sans dépôt ;
- l'absence de nom de recette dans `dataTransfer` ;
- la carte tenue qui garde ses événements ;
- le téléphone inchangé ;
- le focus sur « Annuler ».

Ses constats, revérifiés puis corrigés avec un test ou au banc :

| Gravité | Constat | Correctif |
| --- | --- | --- |
| Haute | Si la carte tenue disparaissait ou changeait de créneau pendant le glisser (relecture du menu, autre appareil), `dragend` n'arrivait plus : `data-holding` restait posé et toute la grille devenait inactive | Repas lâché quand sa carte quitte la semaine ou change de créneau, quand une modification commence, quand la semaine change, et sur `dragend` ou `drop` à la fenêtre |
| Moyenne | Le repas tenu était un instantané : le créneau et la version pouvaient être périmés | Repas relu dans la semaine à chaque survol ; dépôt rejugé avec la version actuelle |
| Moyenne | Le texte du créneau, ajouté dans le flux, faisait grandir la rangée sous le pointeur | Texte posé sur le bas du créneau |
| Moyenne | Firefox ne démarre aucun glisser depuis un bouton (le titre) | Poignée active et plus grande, curseur « main » |
| Moyenne | L'état changeait pendant `dragstart` lui-même, ce qui peut fausser l'image du glisser ou l'interrompre | État posé à la tâche suivante ; un glisser déjà fini ne le pose plus |
| Moyenne | Une autre modification commencée pendant le glisser ne lâchait pas le repas | Repas lâché ; aucun dépôt pendant une modification |

Écartés : un type `none` pour un créneau absent des options (impossible aujourd'hui, `moveOptions` couvre toute la semaine) ; une annonce au lecteur d'écran du texte de survol (« Déplacer… » reste le chemin sans pointeur). À essayer à la main : Firefox et Safari, que le banc ne couvre pas.

## 4. Production

Aucune migration.

**Étapes**, avec l'accord de l'utilisateur :
1. Fusionner après une CI verte. Vercel déploie l'interface.
2. Essai sur ordinateur : glisser un dîner vers un autre jour, puis « Annuler » ; échanger deux repas.

**Retour arrière.** Revenir sur la PR ; « Déplacer… » est inchangé.
