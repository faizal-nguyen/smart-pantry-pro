## 2. Alias de routes (R8)

**Avant.** Deux résolveurs divergeaient :

| Résolveur | Entrées | Défaut |
| --- | --- | --- |
| Routeur | 21 redirections écrites dans `App.tsx`, plus 12 alias générés par `getLegacyRedirections` | `/ai-assistant` et `/assistant-chat` passaient par `/assistant/chat` avant `/assistant` ; `/kitchen-favorites` passait par `/kitchen/favorites`. La requête et l'ancre étaient perdues |
| Retour après connexion (`routineDestination`) | 10 alias dans `legacyPaths` | Tout autre alias retombait sur `/kitchen`. `AuthenticatedLayout` transmet l'adresse brute dans `returnTo`, si bien que `/recipe-catalog`, `/insights-waste`, `/settings/appearance`, `/kitchen/favorites`, `/shopping-legacy`, `/games`… menaient à l'accueil après connexion |

**Après.**
- `LEGACY_ROUTES` regroupe 32 alias, chacun dirigé vers sa cible canonique ; `/games/*` couvre `/games` et ses sous-chemins.
- Comme le routeur, la recherche décode chaque segment et ignore la casse et une barre finale.
- Le routeur génère ses routes d'alias depuis la table (`legacyRedirectRoutes`, `LegacyRedirect`), et le banc V10 aussi.
- `routineDestination` résout l'alias par la même table, puis applique sa liste blanche, **inchangée**.
- **Requête et ancre** :
  - les paramètres propres à l'alias l'emportent, les autres sont conservés ; si la cible n'a pas de requête, celle de l'adresse est gardée telle quelle ;
  - l'ancre de l'alias l'emporte, sinon celle de l'adresse est conservée.
- **Routes de fonctionnalités retirées** : leur destination ne change pas, c'est déjà l'écran le plus proche.

  | Route | Destination |
  | --- | --- |
  | `/games` | `/kitchen/recipes` |
  | `/settings/family`, `/settings/parental` | `/settings` (il n'existe aucune section foyer) |
  | `/shopping/store-mode` | `/shopping/list` |

**Tests.**
- `lib/__tests__/legacy-routes.v10.test.ts` vérifie trois propriétés sur toute la table :
  - aucune cible n'est elle-même un alias (pas de double saut) ;
  - chaque cible passe la liste blanche sans changement ;
  - `routineDestination(alias)` donne la cible.
- Le même fichier couvre aussi la fusion requête et ancre, le décodage, la casse, la barre finale, les clés de prototype, et les garde-fous de connexion (`//`, barre oblique inverse, URL absolue, `/?tab=`).
- `navigation/__tests__/legacy-redirect.v10.test.tsx` vérifie le parcours du routeur : une seule redirection, en remplacement, journal des adresses traversées à l'appui.

## 4. À signaler

- **`/v1/recipes` (hors favoris) et `/v1/users`** n'ont apparemment aucun appelant web : le client n'appelle que `/v1/{client-errors, menus, receipts, recommendations, settings, stock}`. Leur retrait demanderait une preuve refaite route par route : hors du périmètre de R9.
- **`GET /api/v1/recipes/favorites`** retombe désormais sur `GET /:id`. En base, un identifiant non UUID fait échouer la lecture (500), comme aujourd'hui pour tout identifiant non UUID.
- **`apps/api/scripts/fix-rls-routes.sh`**, script ponctuel historique dont le chemin absolu est déjà caduc, cite encore `shopping.routes.ts`. Il est laissé tel quel.

## 5. Relecture

Une relecture indépendante (`typescript-reviewer`) a lu les commits par leurs identifiants. Elle confirme plusieurs points :
- **aucune redirection ouverte** dans `routineDestination` :
  - la sortie est reconstruite à partir du seul chemin, de la requête et de l'ancre ;
  - la liste blanche, ancrée, s'applique au chemin final après alias ;
  - entrées examinées : `//`, `/\`, tabulation, `javascript:`, `@`, `..`, `%2e%2e`, `%2F`, casse, barre finale, fusion de requête ;
- **aucun importeur oublié** de ce qui est retiré, recherché dans le code, les simulations de tests, le banc, l'e2e, les configurations et les scripts ;
- **chaque commit cohérent seul**, aucun ne dépendant d'un commit suivant ;
- **R5** : comportement identique, toutes les branches retirées étaient mortes ;
- **R9** : montages restants et sondes 404 cohérents ;
- **verrou** : 9 entrées retirées, aucune version changée, aucune résolution orpheline.

Ses constats, revérifiés :

| Gravité | Constat | Suite |
| --- | --- | --- |
| Basse | Le test des favoris attendait 404 alors que la vraie base répond 500 (identifiant non UUID, Postgres 22P02) | Le test simule l'erreur réelle et attend 500, dans le commit des favoris |
| Basse | React Router 6.30.1 décode chaque segment avant de comparer : `/%72ecipes` atteignait l'alias `/recipes` dans le routeur, mais pas après connexion | Vérifié dans `@remix-run/router` (`decodePath`). `legacyTarget` décode de la même façon (une barre encodée reste encodée, un échappement invalide est comparé tel quel), test à l'appui, dans le commit R8 |
| Mineure | `legacyTabs` héritait du prototype (`/?tab=constructor`) ; sans effet, la liste blanche le refusait | Recherche par propriété propre : ce paramètre est traité comme un onglet inconnu ; test, dans R8 |
| Mineure | Constante d'origine dupliquée | `ROUTE_ORIGIN`, exportée une fois, dans R8 |
| Mineure | Le banc V10 gardait ses propres redirections (`/pantry`, `/shopping`, `/insights/waste`) | Le banc monte la table partagée, dans R8 (c'est ce qui permet l'essai réel) |
| Mineure | Commentaire périmé dans `e2e/mobile-foundation.spec.ts` (« branche loading » d'`AppNavigation`) | Ajusté, dans R5 |
| Mineure | La fusion de requête réécrit la requête quand l'alias a ses propres paramètres (`%20` devient `+`) | **Accepté** : équivalent pour `URLSearchParams`, et limité aux deux alias des favoris et à `/settings/appearance` |

Les corrections rejoignent le commit de leur lot (commits de correction rattachés, puis `git rebase --autosquash`), et chaque commit est revérifié seul.

## 6. Production

Aucune migration, rien côté Supabase. L'API perd des routes sans appelant.

**Étapes**, avec l'accord de l'utilisateur :
1. Fusionner **par rebase** après une CI verte. Vercel déploie.
2. Vérifier à l'écran :
   - un alias, par exemple `/ai-assistant` ou `/insights-waste`, arrive directement sur son écran ;
   - le menu du compte est inchangé.

**Retour arrière.** `git revert <commit du lot>`. Chaque lot se reprend seul.
