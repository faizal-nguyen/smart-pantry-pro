| Champ | Valeur |

---

## 2. Contexte & probleme adresse

Le besoin utilisateur est de "telecharger et stocker toutes les videos de recettes". Pour une app durable, ce besoin est recadre en archive personnelle :

- Les plateformes sociales ne donnent pas un droit general de telecharger et rehoster les videos sauvegardees.
- Les APIs officielles privilegient metadata, embeds, videos publiques du createur et liens vers la source.
- Le stockage video a un cout fort : upload, transcodage, stockage, CDN, suppression, quotas.
- Les emails/newsletters peuvent contenir images et tracking links.

Ce PRP definit la politique produit et technique :

1. Embed/source first.
2. Pas de downloader Instagram/TikTok automatise.
3. Stockage video brut seulement via upload utilisateur ou permission explicite.
4. Quotas GB/minutes clairs.
5. Pipeline media controle : images, thumbnails, video uploads, lifecycle, suppression.

---

## 3. Objectif

### 3.1 Produit

L'utilisateur a une experience fiable : il voit ses recettes avec images/videos quand c'est possible, sans promesse fausse de "telecharger tout Instagram/TikTok". Quand il possede une video ou l'a obtenue lui-meme, il peut l'uploader comme archive personnelle liee a une recette/import.

### 3.2 Technique

- Politique media appliquee dans le code.
- Tables `media_assets` et eventuellement `media_jobs`.
- Pipeline image/video : upload, validation, metadata, thumbnail job, transcodage optionnel plus tard.
- Quotas par plan : imports, GB, minutes video, extraction IA.
- Suppression RGPD-style : delete user media et jobs.

---

## 4. Non-objectifs

- Pas de contournement de DRM/login/CAPTCHA.
- Pas de scraping agressif de video Instagram/TikTok.
- Pas de downloader TikTok/Instagram automatise en V1.
- Pas de stockage automatique de videos tierces sans autorisation.
- Pas de synchronisation "toutes mes sauvegardes Instagram/TikTok" via APIs privees.
- Pas de CDN maison.

## 5. Specifications detaillees

### 5.1 Politique media

Modes supportes :

| Mode | Description | Stockage interne | Autorise V1 |
|---|---|---:|---:|
| `source_link` | URL originale + metadata | Non | Oui |
| `official_embed` | oEmbed/embed officiel | Non | Oui |
| `thumbnail_snapshot` | Image/cover autorisee ou upload | Oui | Oui |
| `user_upload_image` | Image ajoutee par utilisateur | Oui | Oui |
| `user_upload_video` | Video ajoutee par utilisateur | Oui | Oui, quota |

### 5.3 Table `media_assets`

```sql
CREATE TABLE public.media_assets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  import_id UUID REFERENCES public.social_recipe_imports(id) ON DELETE SET NULL,
  recipe_id UUID REFERENCES public.recipes(id) ON DELETE SET NULL,
  kind TEXT NOT NULL CHECK (kind IN (
    'thumbnail','cover','image','video','audio','transcript','embed_snapshot'
  )),
  origin TEXT NOT NULL CHECK (origin IN (
    'source_link','official_embed','user_upload','personal_archive_upload',
    'permitted_download','generated'
  )),
  rights_status TEXT NOT NULL CHECK (rights_status IN (
    'link_only','user_provided','platform_embed','licensed','unknown','blocked'
  )),
  rights_basis TEXT CHECK (rights_basis IN (
    'created_by_user','user_has_permission','platform_native_download',
    'personal_backup','licensed'
  )),
  rights_policy_version TEXT,
  rights_attested_at TIMESTAMPTZ,
  storage_provider TEXT CHECK (storage_provider IN ('cloudinary','supabase','s3','external')),
  storage_bucket TEXT,
  storage_key TEXT,
  public_url TEXT,
  source_url TEXT,
  mime_type TEXT,
  byte_size BIGINT,
  duration_seconds INTEGER,
  width INTEGER,
  height INTEGER,
  checksum TEXT,
  derived_from_media_asset_id UUID REFERENCES public.media_assets(id) ON DELETE SET NULL,
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb,
  deleted_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_media_assets_user_created
  ON public.media_assets(user_id, created_at DESC);

CREATE INDEX idx_media_assets_import
  ON public.media_assets(import_id) WHERE import_id IS NOT NULL;

CREATE INDEX idx_media_assets_recipe
  ON public.media_assets(recipe_id) WHERE recipe_id IS NOT NULL;
```

RLS :

```sql
ALTER TABLE public.media_assets ENABLE ROW LEVEL SECURITY;

CREATE POLICY media_select_own ON public.media_assets
  FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY media_insert_own ON public.media_assets
  FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY media_update_own ON public.media_assets
  FOR UPDATE USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);
CREATE POLICY media_delete_own ON public.media_assets
  FOR DELETE USING (auth.uid() = user_id);
```

### 5.5 Quotas

V1 :

| Plan | Imports actifs | Images stockees | Video upload (total) | Taille / fichier | Durée / fichier | Extraction IA |
|---|---:|---:|---:|---:|---:|---:|
| Free | 25 | 250 MB | 5 min | 50 MB | 5 min | 10/h |
| Premium | 1000 | 10 GB | 300 min | 500 MB | 30 min | 100/h |

Les quotas doivent etre verifies serveur avant upload.

V1 utilise Supabase Storage avec multipart classique → cap 50 MB / upload sur Free pour rester sous la limite serveur. Les fichiers plus gros (Free 50-100 MB ou Premium > 100 MB) passent par V1.1 upload direct/resumable.

```typescript
export interface MediaQuota {
  maxImageBytes: number;
  maxVideoBytes: number;
  maxVideoSeconds: number;
  maxSingleVideoBytes: number;
  maxSingleVideoSeconds: number; // cap par fichier — évite un .mp4 4h en bitrate très bas qui mange tout le quota
}
```

### 5.6 Endpoint upload image

```http
POST /api/media/images
Content-Type: multipart/form-data
```

Fields :

- `file`: jpg/png/webp/heic.
- `importId?`
- `recipeId?`
- `purpose`: `cover|thumbnail|image`
- `rightsAttestation`: JSON required, meme schema que video.

Processing :

1. Auth.
2. Verifier `rightsAttestation`.
3. Quota.
4. **MIME sniff via `file-type` (npm)** sur les premiers octets du fichier — jamais trust le `Content-Type` header. Reject si mismatch avec extension.
5. **HEIC** : transcoder vers JPEG via `sharp` (déjà dans le stack pour les autres images) avant stockage. iPhone uploade par défaut en HEIC ; un reject silencieux serait piège.
6. **SVG** : reject par défaut (vector exec arbitraire). Un futur PR ajoutera un sanitizer si le besoin émerge.
7. Pas de scan virus en V1 (décision produit : périmètre upload restreint à des comptes auth + cap taille). À reconsidérer si abuse signal.
8. Redimensionner via `sharp` :
   - cover feed : 1080x1920 max.
   - thumbnail : 600x1067 max.
9. Stocker dans Supabase Storage bucket `media-assets` (privé, RLS via storage policy).
10. Creer `media_assets`.

### 5.7 Endpoint upload video

```http
POST /api/media/videos
Content-Type: multipart/form-data
```

Fields :

- `file`: mp4/mov/webm.
- `importId?`
- `recipeId?`
- `rightsAttestation`: JSON required.

`rightsAttestation` :

```typescript
type RightsBasis =
  | 'created_by_user'
  | 'user_has_permission'
  | 'platform_native_download'
  | 'personal_backup'
  | 'licensed';

interface RightsAttestation {
  accepted: true;
  rightsBasis: RightsBasis;
  policyVersion: string;
  sourceUrl?: string;
  originalCreator?: string;
  notes?: string;
}
```

Processing :

1. Verifier `rightsAttestation`.
2. Quota bytes + duration (totaux + cap par fichier `maxSingleVideo*`).
3. MIME sniff via `file-type` + cohérence avec l'extension. Reject si mismatch.
4. Lire metadata duration via `ffprobe` (binaire système — ajout dépendance déploiement) ou `@ffprobe-installer/ffprobe` si pur npm.
5. Stocker l'original dans Supabase Storage bucket `media-assets` (privé) avec clé normalisée `{user_id}/{media_asset_id}.{ext}`.
6. Pas de scan virus en V1 (cf. §5.6).
7. Creer thumbnail job (asynchrone — voir §5.14 job runner).
8. Creer transcript/extraction job optionnel.

Si pas de confirmation :

```json
{
  "success": false,
  "error": {
    "code": "RIGHTS_ATTESTATION_REQUIRED",
    "message": "Confirme la base de droits avant de stocker cette video."
  }
}
```

### 5.8 Embeds officiels

Pour TikTok/Instagram/YouTube :

- Stocker `source_url`.
- Stocker `embed_html` ou `embed_url` seulement si obtenu via endpoint officiel/oEmbed.
- Sanitizer l'HTML embed.
- Ne pas modifier l'attribution.
- Si le contenu devient indisponible, afficher fallback.

Metadata :

```json
{
  "embed": {
    "provider": "tiktok",
    "html": "...",
    "fetchedAt": "2026-05-07T00:00:00.000Z",
    "source": "official_oembed"
  }
}
```

### 5.9 Source snapshots

Meme sans video brute, l'app peut etre durable :

- `source_url`
- `canonical_url`
- `author_name`
- `author_handle`
- `title`
- `description/caption`
- `thumbnail_url` ou cover upload
- `transcript` si autorise/disponible
- `ImportedRecipeDraft`

Cela permet de garder la recette meme si la video disparait, sans rehoster la video.

### 5.10 Lifecycle et suppression

Suppression user :

- Supprimer `media_assets` de la DB.
- Supprimer objets storage.
- Annuler jobs en file.
- Supprimer thumbnails derivees.
- Journaliser `media_asset_deleted`.

Retention :

- Raw email `.eml` : max 7 jours si debug, sinon pas stocke.
- Upload user : jusqu'a suppression user.
- Generated thumbnails : supprimer si asset parent supprime.
- Failed jobs : garder metadata 30 jours.

### 5.11 Security

- Signer les URLs privees si media non public.
- Pas de proxy ouvert : image proxy doit verifier allowlist/import ownership.
- Limiter types MIME.
- Limiter taille fichier.
- Rediger URLs avec tokens dans logs.
- Scanner les SVG ou les rejeter en upload utilisateur V1.

### 5.13 Thumbnail snapshot forcé à la capture

Les URLs CDN Instagram/TikTok sont **signées avec un TTL court** (param `oh=…&oe=…`). Stocker `thumbnail_url` brut sur la ligne `social_recipe_imports` puis l'afficher 6 mois plus tard → 404 garanti.

Règle V1 : à chaque capture sociale réussie, le pipeline télécharge immédiatement la thumbnail OG vers Supabase Storage et crée un `media_assets` avec :

- `kind = 'thumbnail'`
- `origin = 'thumbnail_snapshot'`
- `rights_status = 'platform_embed'` (preview légitime, attribution conservée via `source_url`)
- `rights_basis` = NULL (pas d'upload user)
- `import_id` lié

`social_recipe_imports.thumbnail_url` continue de stocker l'URL distante pour traçabilité, mais le rendering UI utilise en priorité l'URL Supabase via le `media_assets` joint. Si la fetch initiale échoue (réseau, 403, expiry déjà advenue), on garde l'URL distante en fallback et on retente en background une fois.

Implémentation : nouveau service `ThumbnailSnapshotService` invoqué depuis `SocialImportService.capture` après l'insert de la ligne import.

### 5.14 Job runner

`media_jobs` est une queue dans Postgres. V1 livre un consumer simple :

- **Worker Node** dans `apps/api`, démarré par `pm2`/`systemd` à côté du serveur Express.
- Polling `SELECT … FROM media_jobs WHERE status='queued' ORDER BY created_at LIMIT 1 FOR UPDATE SKIP LOCKED` toutes les 5 s.
- Backoff exponentiel sur retry (cap `attempts = 3`).
- Job types V1 : `thumbnail` (extract frame avec ffmpeg), `delete` (cascade storage cleanup).
- Job types V1.1 : `transcode`, `transcript` (Deepgram).

Pas de Redis, pas de BullMQ en V1 — Postgres + `FOR UPDATE SKIP LOCKED` suffit pour notre échelle (< 100 users actifs / mois). Migration BullMQ si on dépasse 1k jobs/jour.

### 5.15 Cost back-of-envelope

V1 cible : 100 users actifs × 2 GB moyen × 5 min vidéo total.

- Storage Supabase : 200 GB × $0.021/GB/mois ≈ **$4.2/mois**
- Bandwidth : ~50 GB/mois lecture × $0.09/GB ≈ **$4.5/mois**
- ffmpeg local : CPU négligeable sur le worker
- Total ≈ **$9/mois pour 100 users** → linéaire jusqu'à ~1k users (~$90/mois) sans changer d'architecture.

Au-delà : passer Cloudinary pour les transformations image dynamiques (économise du stockage côté Supabase) + envisager un CDN dédié (Bunny ~$0.01/GB).

### 5.16 Bridge avec PRP-220.22 (Vault Feed)

Le `RecipeVaultItem.mediaKind` (`image`/`video_embed`/`video_upload`/`none`) doit être hydraté par le hook `useRecipeVaultFeed` à partir de `media_assets` :

```typescript
function resolveMediaKind(item: SocialImport, mediaAssets: MediaAsset[]): RecipeVaultItem['mediaKind'] {
  const userVideo = mediaAssets.find(m => m.kind === 'video' && m.import_id === item.id);
  if (userVideo) return 'video_upload';

  const embed = item.metadata?.embed; // cf. §5.8
  if (embed?.html) return 'video_embed';

  const thumbnail = mediaAssets.find(m => m.kind === 'thumbnail' && m.import_id === item.id);
  if (thumbnail) return 'image';

  return 'none';
}
```

Le `RecipeMediaPreview` (220.22 §5.6) lit en priorité l'URL Supabase via `media_assets.public_url` (signée si bucket privé), puis fallback `social_recipe_imports.thumbnail_url`.

## 7. Etapes d'implementation

### Etape 1 — Policy code

Creer `MediaRightsPolicy.ts`.

```typescript
export function canPersistMedia(input: {
  origin: MediaOrigin;
  rightsAttestation?: RightsAttestation;
}) {
  if (input.origin === 'official_embed') return { allowed: false, mode: 'embed_only' };
  if (input.origin === 'source_link') return { allowed: false, mode: 'link_only' };
  if (input.origin === 'user_upload' || input.origin === 'personal_archive_upload') {
    return input.rightsAttestation?.accepted
      ? { allowed: true, mode: 'store' }
      : { allowed: false, code: 'RIGHTS_ATTESTATION_REQUIRED' };
  }
  if (input.origin === 'permitted_download') return { allowed: true, mode: 'store' };
  return { allowed: false, code: 'MEDIA_RIGHTS_BLOCKED' };
}
```

Creer `media_assets` + `media_jobs` + RLS.

## 8. Tests & validation

### Unitaires

- `official_embed` -> pas de stockage brut.
- `source_link` -> pas de stockage brut.
- `user_upload` sans attestation -> refuse.
- `user_upload` avec attestation -> autorise.

## 10. Risques & mitigations

| Risque | Impact | Mitigation |
|---|---|---|
| Promesse produit trop large | Support | copy claire : embed/source first |
| Cout stockage/CDN | Marge negative | quotas + compression + lifecycle ; cost back-of-envelope §5.15 |
| Upload fichiers dangereux | Secu | MIME sniff `file-type` + cap taille/durée + reject SVG. Pas de virus scan V1 (assumé). |
| HEIC iPhone refusé silencieusement | UX | transcode sharp → JPEG côté serveur (§5.6) |
| Suppression incomplete | Privacy | `MediaLifecycleService` + tests cascade |
| Embeds deviennent indisponibles | UX degradee | source snapshot + draft recette durable + thumbnail snapshot (§5.13) |
| Thumbnails Instagram expirent (TTL CDN) | Cards cassées 6 mois après import | thumbnail snapshot forcé à la capture vers Supabase Storage (§5.13) |
| Job runner Postgres saturé > 1k jobs/jour | Latence thumbnails | migration BullMQ V1.1 si signal |

- Feature flag : `ENABLE_MEDIA_UPLOADS`.

- Ne pas supprimer `media_assets`; seulement cacher actions d'upload.
